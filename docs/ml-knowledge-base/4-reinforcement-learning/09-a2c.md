## 01. Algorithm Overview

| Property | Value |
|---|---|
| Algorithm Name | Advantage Actor-Critic (A2C) |
| Category | Reinforcement Learning (RL) |
| Type | On-policy, stochastic policy-gradient, actor-critic |
| Parametric / Non-parametric | Parametric (neural networks) |
| Generative / Discriminative | Actor samples actions |
| Main Objective | Maximize return via ∇J = E[Σ γ^t ∇log π_θ(a_t\|s_t)·(R_t − V_φ(s_t))] with synchronized workers |
| Input | State observations and rewards from parallel environments |
| Output | Policy π_θ(a\|s) and value V_φ(s) |
| Core Idea | Use an advantage (return minus critic's value estimate) as the weight, trained across **synchronized parallel workers** |
| Typical Use Cases | Discrete control, parallel environments, medium-scale continuous tasks |

---

## 02. One-Line Definition

### Beginner Definition
A2C trains two networks together — an actor that picks actions and a critic that predicts how good a state is — then nudges actions favored by the difference (advantage), running several copies of the environment in sync so training data is batched efficiently.

### Technical Definition
A2C estimates the policy gradient as
`∇_θ J(θ) = E[ Σ_t γ^t ∇_θ log π_θ(a_t|s_t) · A(s_t,a_t) ]`
with advantage `A(s,a) ≈ Q(s,a) − V_φ(s) ≈ R_t − V_φ(s_t)`. It is the **synchronized** counterpart of A3C: multiple workers each compute gradients in parallel, then are aggregated before a shared update.

---

## 03. Intuition

- **Actor = who does; Critic = how good is it?** The actor decides actions; the critic grades states.
- **Advantage = surprise.** Instead of "this action led to reward r", we ask "was this action better than the *average* outcome from this state?" Positive advantage → reinforce; negative → discourage.
- **Parallelism:** many environment copies run in lockstep. Each gathers a small trajectory (e.g., n=5 steps), all gradients are averaged, one shared network updates — this is **synchronous**.
- This lowers variance (baseline) and speeds data collection (parallel batch) — the core A2C mechanism.

---

## 04. Problem It Solves

- **High variance in REINFORCE:** a Monte-Carlo return as direct weight is noisy. The **critic baseline** V(s) subtracts the expected value, yielding the advantage — much lower variance.
- **Slow data collection:** single-threaded rollout wastes wall-clock. Running many environments in parallel provides a large, diverse batch per update.
- **A3C's nondeterminism:** A3C updates asynchronously (workers race). A2C **synchronizes** them: deterministic, more stable, GPU-friendly batching.

## 08. Mathematical Foundation

Policy gradient theorem inner product formulation. For any baseline b(s) independent of a,

```
∇_θ J(θ) = E[ Σ_t γ^t ∇_θ log π_θ(a_t|s_t) · (Q^π(s_t,a_t) − b(s_t)) ]
```

Setting `b(s_t) = V_φ(s_t)` turns the bracket into the **advantage**:

```
A(s_t,a_t) = Q(s_t,a_t) − V_φ(s_t) ≈ R_t^{(n)} − V_φ(s_t)
```

where `R_t^{(n)}` is the n-step return — the trajectory's sampled rewards up to horizon n, then bootstrapped with the critic:

```
R_t^{(n)} = r_t + γ r_{t+1} + ... + γ^{n-1} r_{t+n-1} + γ^n V_φ(s_{t+n})
```

The critic is trained to fit these returns: `L_critic = (V_φ(s_t) − R_t^{(n)})²`.

---

## 09. Core Formula

The A2C policy-gradient update:

```text
∇_θ J(θ) = E[ Σ_t γ^t ∇_θ log π_θ(a_t|s_t) · ( R_t − V_φ(s_t) ) ]
```

### Meaning
Each action's gradient is scaled by how much better (or worse) its outcome (return R_t) was compared to the critic's prediction V_φ(s_t).

### Symbols
- `θ` actor params, `φ` critic params.
- `π_θ(a|s)` policy likelihood.
- `R_t` return estimate (n-step).
- `V_φ(s_t)` critic's value prediction — the baseline.
- `γ` discount.
- `∇_θ log π_θ` the score function (likelihood-ratio gradient).

### Intuition
Actions with `R_t > V(s_t)` (better than expected) get reinforced; with `R_t < V(s_t)` get suppressed. The baseline does not change the expectation but cut variance hugely.

### Example (tiny dataset, hand-verified)
Suppose one worker's 3-step rollout, γ=0.99, n=3:

| t | r_t | V_φ(s_t) |
|---|---|---|
| 0 | +1 | 0.8 |
| 1 | +2 | 1.5 |
| 2 | 0 | 2.0 |

`R_0 = 1 + 0.99·2 + 0.99²·0 + 0.99³·2.0 = 1 + 1.98 + 0 + 1.9406 ≈ 4.9206`.
`A_0 = R_0 − V(s_0) = 4.9206 − 0.8 ≈ 4.12`. This positive advantage reinforces a_0.
`R_1 = 2 + 0.99·0 + 0.99²·2.0 = 2 + 0 + 1.9602 ≈ 3.96`; `A_1 = 3.96 − 1.5 = 2.46`.
If a_0 (log-prob 0.5, score 1.0) with A_0: gradient contribution `γ^0·1.0·4.12 = 4.12`.

---

## 10. Derivation

Start from the score-function trick: `∇_θ π_θ(a|s) = π_θ(a|s) ∇_θ log π_θ(a|s)`.

```
∇_θ J = ∇_θ E[R(τ)]
      = E[ R(τ) Σ_t ∇_θ log π_θ(a_t|s_t) ]
```

This is REINFORCE. Subtract a baseline b(s_t) that doesn't depend on a_t:

```
E[ b(s_t) ∇_θ log π_θ(a_t|s_t) ] = Σ_a π_θ(a|s) b(s) ∇_θ log π_θ(a|s)
   = b(s) Σ_a ∇_θ π_θ(a|s) = b(s) ∇_θ Σ_a π_θ(a|s) = b(s) ∇_θ 1 = 0
```

So the baseline is unbiased. Choosing `b = V_φ(s)` gives the advantage:

```
∇_θ J = E[ Σ_t γ^t ∇_θ log π_θ(a_t|s_t) · A(s_t,a_t) ]
```

Replacing the full return with the n-step return + bootstrapping reduces variance further (truncation) at a small bias.

## 11. How the Algorithm Works

```text
Input: N workers, actor π_θ, critic V_φ
  ↓
Each worker runs n steps (same policy) → store (s,a,r,V(s))
  ↓
Compute n-step returns R_t and advantages A_t = R_t − V(s_t)
  ↓
Synchronize: sum gradients across all N workers
  ↓
Actor: θ ← θ + α ∇_θ ( Σ log π_θ · A + β·H )
Critic: φ ← φ − α ∇_φ ( Σ (V(s_t) − R_t)² )
  ↓
Broadcast updated θ, φ to all workers
  ↓
Repeat until convergence
```

---

## 12. Training Process

- **Pre-training:** initialize networks; reset all N workers.
- **During:** each worker experiences n steps; advantages computed; gradients aggregated (synchronized) across workers; one shared update; results broadcast back.
- **What's learned:** θ (policy) and φ (value).
- **Change per iteration:** θ toward higher-advantage actions; φ toward the true value.
- **Stopping:** return plateaus or budget exhausted.
- **Final model:** policy + value network.

---

## 13. Objective Function / Loss Function

Two coupled objectives:

```
Actor: J(θ) = Σ_t [ log π_θ(a_t|s_t) · A_t ] + β · H(π_θ(·|s_t))
Critic: L(φ) = Σ_t ( V_φ(s_t) − R_t )²
```

- **Actor loss (negated for descent):** `−Σ log π_θ(a|s)·A − β·H`. Maximizes probability of good-advantage actions; entropy keeps it exploring.
- **Critic loss:** MSE between predicted value and observed return — trains the baseline.

---

## 14. Optimization

Method: synchronized stochastic gradient ascent on θ (descent on the negated actor loss) and descent on φ.

```text
Current θ, φ
  ↓
Advantages A from n-step returns
  ↓
Actor grad: Σ log π_θ · A + β ∇H
Critic grad: ∇(V−R)²
  ↓
θ ← θ + α·(actor grad); φ ← φ − α·(critic grad)
  ↓
Broadcast to workers
```

---

## 15. Complete Numerical Example

**VERIFIED EXAMPLE** (hand-verified above).

**Setup.** One worker, γ=0.99, n=3, β=0.01, learning rate α=0.1. Suppose the policy is a softmax over 2 actions. Log-probability score for the taken action `a_0`: `g = ∇_θ log π_θ(a_0|s_0) = 1.0` (component of interest). Entropy gradient ≈ 0.02 (small).

**Step 1 — returns:** as computed: `R_0 ≈ 4.9206`, `R_1 ≈ 3.9602`, `R_2 = 0 + 0·? ... ` (skip).
**Step 2 — advantages:** `A_0 = 4.9206 − 0.8 = 4.1206`, `A_1 = 3.9602 − 1.5 = 2.4602`.
**Step 3 — actor gradient:** `Σ γ^t g_t A_t = 1.0·4.1206 + 0.99·g_1·2.4602 ...`.
**Step 4 — update (γ^0 term):** `θ += 0.1 · (4.1206 + 0.01·0.02) ≈ 0.1·4.1208 ≈ 0.412`.
**Step 5 — critic update:** residual `V(s_0)−R_0 = 0.8 − 4.9206 = −4.1206`; MSE`≈ 16.98`; gradient w.r.t φ pulled toward 4.9206.

The positive advantage strengthens `a_0`'s probability.


## 18. From-Scratch Implementation

Minimal NumPy sketch (update equations appear literally):

```python
import numpy as np

def a2c_update(theta, phi, workers_data, lr=0.1, gamma=0.99, beta=0.01):
    grad_policy = np.zeros_like(theta)
    grad_value = np.zeros_like(phi)
    # workers_data: list per worker of (states, actions, rewards, values)
    for worker in workers_data:
        states, actions, rewards, values = worker
        T = len(rewards)
        # n-step returns and advantages
        R = np.zeros(T)
        g = values[-1]  # bootstrap from final critic value
        for t in reversed(range(T)):
            R[t] = rewards[t] + gamma * g
            g = R[t]  # n-step bootstrap approximated; use terminal otherwise
        A = R - values  # advantage = return minus critic
        # actor gradient (score * advantage) + entropy term
        for t in range(T):
            grad_policy += log_pi_grad(theta, states[t], actions[t]) * A[t]
        # critic gradient (MSE)
        grad_value += 2 * (values - R)
    theta += lr * (grad_policy + beta * entropy_grad(theta, states))
    phi -= lr * grad_value
    return theta, phi
```

Equations: `R[t] = r + γg` (return), `A = R − V` (advantage), `θ += lr·Σ∇logπ·A` (policy update), `φ −= lr·Σ(V−R)` (critic update).

## 20. Library Implementation

CleanRL-style A2C (PyTorch, vectorized envs):

```python
import torch, torch.nn as nn

class A2C(nn.Module):
    def __init__(self, obs_dim, act_dim):
        super().__init__()
        self.policy = nn.Sequential(nn.Linear(obs_dim, 64), nn.Tanh(),
                                    nn.Linear(64, 64), nn.Tanh())
        self.pi = nn.Linear(64, act_dim)
        self.value = nn.Linear(64, 1)

    def forward(self, x):
        h = self.policy(x)
        return self.pi(h), self.value(h)

# in the update loop:
logits, values = model(obs)
dist = torch.distributions.Categorical(logits=logits)
log_prob = dist.log_prob(actions).unsqueeze(1)
entropy = dist.entropy().unsqueeze(1)
advantage = returns - values
policy_loss = -(log_prob * advantage).mean() - 0.01 * entropy.mean()
value_loss = 0.5 * ((returns - values) ** 2).mean()
loss = policy_loss + 0.5 * value_loss
```

`returns` come from GAE/n-step, `advantage = returns − values` matches the formula.

## 23. Assumptions

- **Markov property** — state captures history; violate → memory/RNN.
- **Stationary environment** — parallel workers sample same distribution; if workers differ, bias.
- **Synchronized workers share a consistent policy** — a barrier ensures all grads from same θ.
- **Bounded rewards** — extreme reward scales destabilize advantage.

---

## 24. Data Requirements

- Data: state-action-reward from parallel rollouts (self-generated, no labels).
- Numerical features; scale observations.
- Sample efficiency: low-medium (on-policy).
- Many workers give diverse data, but each is fresh (frequent restart).

---

## 25. Feature Scaling

**Recommended.** Normalize observations (running mean/std); normalize advantages per batch. Improves stability and speed.

---

## 26. Evaluation Metrics

| Metric | Definition | Use |
|---|---|---|
| Mean episode return | Average reward sum over eval | Primary performance |
| Mean episode length | Steps to terminal | Progress/timeout |
| Learning curve (return vs steps) | Over training | Sample efficiency/stability |
| Policy entropy | H(π(·\|s)) | Exploration (shouldn't collapse early) |

Do not judge by actor/critic loss.

---

## 27. Advantages

- **Lower variance** via advantage baseline vs REINFORCE.
- **Synchronous & deterministic** aggregation (vs A3C race).
- **Parallel data** — faster wall-clock, GPU-friendly batched updates.
- **Simple** to implement and reason about; natural stepping stone to PPO.

---

## 28. Disadvantages

- **Sample-inefficient** — on-policy, discards data each update.
- **Fixed n-step horizon** — tuning n is a bias/variance trade.
- **Slower than async** for some single-threaded setups; sync barrier can stall on stragglers.
- **Less principled trust region than PPO** — can still make destabilizing jumps.

---

## 29. When to Use

- ✓ Medium-scale, parallelizable environments.
- ✓ Discrete or continuous actions with a stochastic policy.
- ✓ Want a simple, well-understood actor-critic baseline.
- ✓ Wall-clock speed matters and you have many envs.

---

## 30. When NOT to Use

- ✗ Very sample-constrained (real robots) → off-policy SAC/TD3.
- ✗ Need maximum stability → PPO's clip is stronger.
- ✗ Deterministic, sample-rich → DDPG/TD3 style.
- ✗ Data must be reused → on-policy requirement blocks it.

## 32. Failure Cases

- **Entropy collapse** — policy becomes deterministic too early.
- **Critic inaccurate** — advantage mis-signed → wrong reinforcement.
- **Sync barrier straggler** — one slow worker stalls all.
- **n-step too long/short** — variance vs bias imbalance.
- **Worker distribution drift** — non-stationary grad.

---

## 33. Overfitting and Underfitting

- **Overfitting:** replay of same-worker data with many epochs (A2C typically single-epoch) memorizes trajectories; add entropy, more workers.
- **Underfitting:** small network / short rollouts cannot capture behaviors; enlarge capacity.
- Balance by watching return curves and entropy.

---

## 34. Bias-Variance Perspective

- Advantage baseline removes variance; introduces critic bias.
- n-step truncation: low n = lower variance/higher bias; high n = opposite.
- Entropy adds a slight bias reducing premature convergence.
- Parallel workers average independent actions → variance reduction across the batch.

## 37. Common Mistakes

```text
❌ Forgetting the baseline (using raw return)
Why wrong: high variance.
Correct: subtract V_φ(s_t).

❌ Not synchronizing before the update
Why wrong: gradient from mismatched policy (becomes A3C).
Correct: barrier / aggregate all workers.

❌ Setting n-step too long
Why wrong: variance explodes.
Correct: n=4–5 with γ=0.99.

❌ Judging by actor loss going down
Why wrong: loss ≠ performance.
Correct: watch mean return.
```

## 38. Interview Questions

### Beginner
- **Q: What is the actor? Critic?** A: Actor is policy; critic predicts state value (baseline).
- **Q: What is an advantage?** A: How much better the action did than the state's expected value: R − V(s).
- **Q: What does "synchronized" mean?** A: All workers' gradients merge before the single shared update.

### Intermediate
- **Q: How does A2C reduce variance?** A: Advantage baseline subtracts expected value, and n-step truncation.
- **Q: Why parallel workers?** A: Diverse batch data, faster wall-clock, variance reduction.
- **Q: What is the baseline bias guarantee?** A: b(s) independent of a has zero contribution to the expectation (score trick).

### Advanced
- **Q: Difference between A2C and A3C?** A: A2C syncs gradients; A3C lets workers update asynchronously.
- **Q: Why truncate to n-step?** A: Balance bias (short horizon) vs variance (long).
- **Q: Add trust region?** A: Use clip (PPO) on the same actor-critic gradient.

- Space: keeps only current n-step buffer (N×n states).
- Scales well with more workers up to resource limits.
